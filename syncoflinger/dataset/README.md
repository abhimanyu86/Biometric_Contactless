# Synthetic contactless fingerprint dataset (v1, 50 images)

Generated by `syncoflinger/build_dataset.py`: 10 distinct synthetic fingers
(Anguli, `seed=777`, natural class distribution) x 5 mated samples each
(2 high / 2 medium / 1 low quality, via `contactless_transform.py`),
each with ground-truth minutiae propagated through the full transform chain.

## Layout

- `images/<finger_id>_<quality>_<NN>.png` — the generated contactless-style image
- `minutiae/<finger_id>_<quality>_<NN>.json` — matching ground truth: list of
  `{x, y, direction, type}`, `type` is `"RIG"` or `"BIF"`, `direction` in
  radians (`atan2(sin, cos)` convention, matching this project's real
  `detect_minutiae` output)
- `manifest.json` — index of all 50 samples (finger/quality/paths/minutiae count)
- `diversity_montage.png` — one "high" sample per finger, for a quick visual check

## A real quality issue found and fixed while building this batch

The first generation pass had a genuine bug, not just cosmetic variance:
measured luminance contrast (std) ranged from 15.9 to 88.1 across the 50
images, and some "high quality" draws were *less* readable than "low
quality" ones -- random skin-tone/shadow-angle/brightness combinations
occasionally compounded into a nearly-unreadable image. A capture that
washed out would fail real QC (blur/brightness) before ever reaching an
extractor, so shipping it as labeled "high quality" training data would
have been actively misleading. Fixed with a contrast-floor step in
`contactless_transform.py` (mirrors this project's own real pipeline,
which does the same kind of correction for genuinely low-contrast
captures) -- worst case improved from std=15.9 to std=38.8, much closer
to the 46.7 median.

## Honest scope

10 distinct base fingers is small -- real diversity (ridge topology
variety) is limited, and this batch shouldn't be mistaken for anything
beyond an early Stage B pipeline-validation set. Scaling this up (more
Anguli fingers, more mated samples, more skin-tone presets) is a config
change to `build_dataset.py`'s `SAMPLE_PLAN` and Anguli's `-num`, not new
code -- worth doing once this format is confirmed to actually work in
Stage B's training-target generator.
