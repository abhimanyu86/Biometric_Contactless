# Cloud service (cloud_app.py) dependencies only — templatization + matching.
#
# Deliberately excludes ultralytics, tensorflow, mediapipe, scikit-image, and the
# dev-tooling set (streamlit, pandas, altair, matplotlib, requests, scikit-learn).
# Those are what YOLO/liveness/U2Net/Zero-DCE/labtool/benchmark.py need — none of
# them run in this process. See the split table in the architecture plan for the
# full reasoning.
#
# torchvision IS needed here (unlike the note that used to be on this line): the
# CNN/Siamese embedding matcher (embedding_matcher.py, /v2/*_embedding endpoints)
# uses torchvision's pretrained ResNet18 as its feature extractor. This is a
# cloud-tier need, not an on-device one — nothing about the on-device-tier
# exclusions above has changed.
#
# torchvision is intentionally left unpinned (unlike every other dependency in
# this file): torchvision hard-pins an exact required torch version internally
# (confirmed via a failed build: "torchvision 0.19.0+cpu depends on
# torch==2.4.0", which conflicts with torch==2.12.0+cpu pinned below). Pinning
# torchvision here to whatever version happened to work in dev (0.19.0, paired
# with torch==2.4.0 there) breaks the build against this file's torch==2.12.0+cpu.
# Leaving it unpinned lets pip's resolver pick whichever torchvision release
# actually requires torch==2.12.0 -- if this ever fails to resolve, torch's own
# release notes list the correct torch/torchvision pairing.
#
# networkx IS needed, despite matching.py only using "legacy" in production:
# matching.py imports the entire algorithms/ package unconditionally at module
# load time (to populate its algorithm registry), and algorithms/networkx_graph.py
# does a bare `import networkx` — so it's a real import-time dependency of
# matching.py regardless of which algorithm ever actually gets selected at
# runtime. It happens to already be pulled in transitively by torch today
# (confirmed: `pip show networkx` reports "Required-by: torch"), which is why
# this was previously omitted without anything breaking — but that's an
# implicit, unpinned dependency this file shouldn't rely on staying true across
# a future torch version bump. Pinning it explicitly here.

# torch's default PyPI wheel bundles full CUDA/cuDNN (~4GB of nvidia-* packages)
# for GPU support this service never uses — this VM has no GPU. The +cpu build
# from PyTorch's own CPU-only wheel index avoids that entirely.
--extra-index-url https://download.pytorch.org/whl/cpu
